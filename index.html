INTELCOM ● Data Tools

Three browser tools for building and running the unified data standard. Each is a single HTML file with no dependencies — they work opened straight from disk and from a static host alike, and nothing you load ever leaves your machine.

JSON ● Workbench

Edit, inspect and convert the records themselves.

  • View & edit as text or as a collapsible tree, with inline editing, add/delete/reorder and undo
  • Verify syntax with line and column, and validate against a JSON Schema — cross-file $ref included
  • Convert to and from CSV and XML
  • Query with JSONPath-lite, and read metrics: shape, type spread, per-field fill rates
  • Records tab with a schema-generated form for adding, editing and deleting entries

Reach for this when the thing you are working on is the data.

Schema ● Studio

Keep every schema coordinated with the master.

  • Matrix of properties against schemas, resolved through allOf and $ref, so inherited fields show up too
  • Edit any property in place, and push the same definition into several schemas at once
  • Side by side raw editors, two to four panes, with synced scrolling
  • Diff any two files path by path
  • Check for dangling $refs, duplicate $ids, fields the master would reject, and properties worth promoting into it

Reach for this when the thing you are working on is the shape.

Data ● Mapper

Migrate a source system into the new standard.

  • Read CSV, TSV, JSON, NDJSON and SQL dumps — columns from CREATE TABLE, rows from INSERT
  • Map field to field, with auto-matching on names and synonyms, and a live result for row 1
  • Transform with dates, splits, lookups, templates, coalesce, lat/lon pairs, generated ids
  • Preview the output validated against the target schema, problems listed by row and path
  • Save mappings to a library and export them as files you can commit

Reach for this when the thing you are working on is the move.

How they fit together

  1. Studio — settle the target shape, and keep the type schemas in step with record.schema.json.
  2. Mapper — point each legacy source at that shape, save the mapping, run the migration.
  3. Workbench — open the result, check it, fix what needs fixing, and maintain it from there.

Schemas live in mdm-v1/ — the master envelope in record.schema.json, the per-type schemas in types/, worked examples in examples/. All three tools load them by file or drag-and-drop; the Studio can also open the whole folder at once. Each tool keeps its working state in browser storage, so a reload does not lose anything, and that storage is per-origin — a local copy and a hosted copy keep separate state.
